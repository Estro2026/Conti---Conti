# Mockup Plan

## 1. Quando usare questo documento

Usare il mockup per:

- siti multipagina dopo approvazione del wireframe;
- landing page;
- one-page;
- progetti in cui la struttura è già definita e approvata;
- redesign visuali senza revisione sostanziale dell'architettura.

## 3. Obiettivo del mockup

Definire in modo completo:

- tipografia;
- palette;
- immagini;
- componenti;
- stati;
- responsive;
- motion;
- accessibilità;
- comportamento frontend;
- consistenza tra pagine.

## 4. Gerarchia visiva

Per ogni pagina verificare:

1. Hero
2. Titolo sezione
3. Sottotitolo
4. Contenuto principale
5. CTA
6. Elementi secondari
7. Meta / label

La gerarchia deve restare riconoscibile anche su schermi zoomati e mobile.

## 8. Image Direction

Per ogni immagine:

- funzione;
- fonte;
- soggetto;
- crop;
- aspect ratio;
- focal point;
- desktop;
- tablet;
- mobile;
- eventuale trattamento;
- formato finale;
- peso;
- alt text se informativa.

## 9. Motion Direction

Per ogni animazione:

- elemento;
- trigger;
- comportamento;
- durata;
- easing;
- desktop;
- touch;
- mobile;
- fallback;
- prefers-reduced-motion;
- impatto performance;
- note sviluppo.

Non aggiungere motion senza funzione comunicativa o UX.

## 10. Responsive

Il mockup deve coprire almeno:

- desktop;
- laptop;
- schermi zoomati;
- tablet;
- mobile;
- touch.

Fare riferimento a `responsive-spec.md`.

## 11. Schermi zoomati

Controllare:

- hero title;
- titoli sezione;
- form;
- card;
- composizioni orizzontali;
- navigazione;
- CTA;
- immagini;
- overflow;
- sticky;
- elementi decorativi;
- sezioni full viewport.

Non cambiare struttura automaticamente se il layout può ancora funzionare.

## 12. Mobile

Verificare:

- ordine contenuti;
- priorità;
- dimensioni testo;
- CTA;
- menu;
- form;
- immagini;
- touch;
- sticky;
- modal;
- carousel;
- tabelle;
- footer.

## 13. Content Review

Prima della consegna il Content Agent deve controllare:

- italiano;
- grammatica;
- sintassi;
- tono;
- microcopy;
- titoli;
- CTA;
- ripetizioni;
- lunghezza;
- gerarchia;
- contenuti mancanti.

## 14. Image Review

L'Image Curator deve controllare:

- coerenza con art direction;
- qualità;
- risoluzione;
- crop;
- aspect ratio;
- formato;
- peso;
- eventuali duplicazioni;
- uso corretto su desktop/mobile;
- immagini decorative/informative;
- alt text.

## 15. Accessibility Review

## 16. SEO Review

## 18. Note sviluppo

Ogni comportamento non evidente dal mockup deve avere una nota.

Formato:

`DEV — comportamento / responsive / interaction / CMS / stima`

## 19. Stima sviluppo

Aggiornare `development-notes.md` sulla base del mockup finale.

- responsive;
- JS;
- motion;
- CMS;
- integrazioni;
- QA;
- accessibilità;
- browser testing.

- [ ] Bozza
- [ ] Review interna
- [ ] Pronto per cliente
- [ ] Inviato
- [ ] Feedback ricevuti
- [ ] Modifiche applicate
- [ ] Approvato
- [ ] Pronto per sviluppo

## 25. Passaggio successivo

Quando il mockup è approvato:

`Mockup approvato → Final QA → Development Handoff`

## 26. Regola finale

Il mockup non è considerato completo solo perché appare corretto visivamente.

Deve essere:

- comprensibile;
- responsive;
- accessibile;
- sviluppabile;
- coerente;
- performante;
- documentato.
